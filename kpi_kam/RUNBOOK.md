# Работа с общим файлом продаж

## Первый запуск

1. Распакуйте **весь** Windows artifact. В одной папке должны находиться
   `KPI_KAM.exe` и `_internal`. Запустите exe двойным щелчком.
2. Откройте «Администратор», введите начальный пароль `Innovanta_20102026`,
   нажмите «Войти». Пароль применяется только при первом создании БД;
   существующий измененный пароль не заменяется.
3. На вкладке «Смена пароля» задайте свой пароль длиной минимум 10 символов.
   Сессия администратора заканчивается по «Выйти» или при закрытии программы.
4. На вкладке «Прайс-лист» нажмите «Импорт отдельного прайс-листа» и выберите
   `прайс 2026 для расчета KPI.xlsx`. Встроенный лист «прайс» общего файла
   продаж программа не использует. Каждый успешный импорт создает версию.
5. На вкладке «Сотрудники» выберите сотрудника, год и должность, нажмите
   «Задать должность на год». Для нового сотрудника/года это обязательно.
   Роли: КАМ или Менеджер сопровождения. Должность не угадывается из имени.
   При смене сотрудника или года поле показывает сохраненную должность
   именно для этой пары. «Не задана» означает, что назначения еще нет.
   После выбора другой должности нажмите кнопку сохранения; под ней
   появится подтверждение с сотрудником, годом и сохраненной должностью.
6. Начальный список включает Пермякову Анну, Трофимова Дмитрия,
   Погорельцеву Елену, Долгополову Марию, Гайдину Юлию, Петрову Елену
   и Филимонову Анну. Их фамилии распознаются через сохраненные алиасы.

## Импорт продаж

1. На «Новый расчет» выберите год. Нажмите «Импорт общего файла продаж».
   Выберите `Копия Продажи 2026_ (002).xlsx`.
2. Импорт читает два листа: «контракты СБКС, ВМК» и «контракты ЭП».
   Месячные группы определяются по Excel-дате первого числа месяца,
   возвраты — по названиям «Возврат апрель» и аналогичным.
3. Если не найдены заголовки, нажмите «Подтвердить структуру листа».
   Это действие доступно администратору. В открывшемся окне посмотрите
   строки и выберите каждую колонку, затем строку непосредственно перед
   данными. Нажмите OK. Если допущена ошибка, импорт сообщит о ней и не
   заменит последний успешно сохраненный файл.
4. В приложенном листе ЭП отсутствуют обязательные заголовки. Для **этого
   конкретного файла**, после проверки предпросмотра: строка перед данными 11,
   ФО A, Регион B, Менеджер C, ЛПУ/КА G, ДБ I, Отгрузка ЮЛ K,
   Номер контракта L, Наименование P. Это подсказка для ручного подтверждения;
   в коде автоматического переноса этих букв нет. При измененной структуре
   выбирайте колонки по данным.
5. Строки менеджера «тендер» исключаются. Регистр, NBSP и лишние пробелы
   не влияют на сравнение. Счетчик исключений показан на главном экране.
6. Неизвестный менеджер остается в импортированных событиях. В Admin →
   Сотрудники его имя показано в списке проблем. Можно выбрать существующего
   сотрудника, ввести имя из файла в source alias и сохранить. Для нового
   сотрудника введите правильное полное ФИО, source alias и нажмите
   «Добавить сотрудника», затем задайте должность на год.
   В приложенном файле такого решения требует **Бабенкова**.

## Сопоставления и расчет

1. Выберите сотрудника и год, введите планы Q1–Q4. Нулевой план допустим,
   пустой — нет. Для сопровождения также введите факты звонков; исходный
   план звонков 750 в каждом квартале. Нажмите «Сохранить планы и звонки».
   После перезапуска эти значения восстанавливаются.
2. Откройте «Сопоставление». Для каждой нерешенной строки выберите товар
   из внешнего прайса и нажмите «Подтвердить и сохранить алиас».
   Группа и оба порога берутся только из выбранного товара прайса.
   Программа не угадывает товар по префиксу или похожему имени.
3. Если товара действительно нет в действующем прайсе, можно явно нажать
   «Оставить вне зеленой зоны». Выручка сохранится в факте плана,
   строка будет исключена из премиальной базы. При новом прайсе такое
   решение нужно подтвердить снова. Для обычных несовпадений используйте
   сопоставление с правильным продуктом, а не исключение.
4. Нажмите «Рассчитать премию». Отгрузки, возвраты и расчет сохраняются
   в историю вместе с прайсом, ролью, ставками и планами.
5. В «Отгрузки» видны месяцы, клиенты, продукты, группы, цена и порог
   после округления до одного знака, eligibility и источник каждой строки.
   Пустые маркеры ДБ (`-`, `нет`, `не указан`, `n/a` и др.) означают ЛПУ;
   заполненная ДБ означает дистрибьютера.
6. В «Возвраты» показаны исходные продажи и остаток для сверки. Возврат
   всегда уменьшает факт квартала своего появления. FIFO распределяет
   возврат только на предыдущие продажи той же контрактной строки/товара.
   Нераспределенная часть не создает автоматического clawback.
   Администратор может выбрать исходную отгрузку кнопкой сверки.
7. В «Премия» показаны план, факт до/после возвратов, четыре базы/ставки/
   премии, звонки, clawback, перенос и payable. Поиск работает во всех таблицах.

## Подтверждение выплаты и поздние возвраты

1. После проверки расчета выберите квартал внизу «Премия». По умолчанию
   сумма равна payable; при необходимости введите фактически выплаченную.
   Нажмите «Подтвердить выплату» и подтвердите действие.
2. Выплаты подтверждаются в хронологическом порядке. Повторно подтвердить
   один Employee + Year + Quarter нельзя. Расчет после подтверждения закрыт.
   Для следующего квартала выполните новый расчет.
3. Закрытый snapshot не переписывается новым прайсом, настройками или
   импортом. Планы и звонки оплаченного квартала фиксируются.
4. Возврат до выплаты уменьшает исходную премиальную базу, в том числе
   через границу года: для неоплаченного прошлого года сохраняется новый
   исправленный snapshot. Возврат после
   выплаты eligible-продажи создает clawback с **исходной** ставкой/ролью.
   Остаток сверх текущей премии переносится вперед; payable неотрицателен.
   Возврат по исключенной продаже уменьшает только факт, clawback равен 0.
5. Поздняя корректировка закрытого периода назначается первому открытому
   кварталу. Изменение/удаление уже оплаченной отгрузки блокирует расчет
   и требует сверки исходного файла: такой ввод нельзя считать новой продажей.
6. Q4 при годовом выполнении ≥90%: годовая расчетная премия минус **реальные**
   выплаты Q1–Q3, затем текущие корректировки и остаток. Согласно выбранному
   варианту пользователя прежние удержания Q2/Q3 дополнительно не вычитаются;
   буквальный catch-up может их возместить. Для сопровождения звонки каждого
   квартала входят в годовую премию один раз. Если годовой gate не пройден,
   применяются обычный Q4 gate и премия Q4.

## Экспорт, история и резервные копии

* Двойной щелчок в «История» открывает сохраненный snapshot. Исходный Excel
  больше не нужен. «Старая история» сохраняет доступ к расчетам прошлого формата.
* Admin → Экспорт: выберите одного или всех сотрудников, год и квартал либо
  весь год. XLSX содержит сводку, включенные/исключенные отгрузки, возвраты,
  корректировки, планы и параметры. Сводка использует последний сохраненный
  расчет каждого сотрудника/года; перед экспортом новых продаж пересчитайте их.
  Decimal сохраняется текстом с полной точностью, чтобы Excel не обрезал
  числа до 15 значащих цифр. Названия также сохраняются текстом, без формул.
* Admin → История / Сброс: две последовательные кнопки подтверждения.
  До удаления SQLite создает backup в `%APPDATA%\KPI_KAM\backups`.
  История, выплаты, ledger и продажи удаляются; сотрудники, алиасы, прайсы,
  должности, планы, настройки и пароль сохраняются. Повторный импорт после
  сброса начинается с чистого учета возвратов.
* При первой миграции существующей БД также создается backup. Не удаляйте
  свою БД перед установкой обновления. Для восстановления закройте приложение,
  сохраните текущую БД отдельно и скопируйте нужный backup на ее место.

## Ограничения источников

Excel читается без запуска VBA, пересчета формул и внешних ссылок. Формулы
с месячными количеством/суммой без сохраненного результата являются ошибкой.
Пустые шаблонные строки без движения пропускаются. Количество 0 при ненулевой
сумме остается ошибочной строкой аудита и не получает eligibility.
`.xls`, защищенные паролем и поврежденные книги не поддерживаются.
