# KPI KAM — desktop GUI

Реализованы PySide6 GUI, Excel-импорт/валидация и чистое расчётное ядро:
неизменяемые модели, точный матчинг/явные алиасы, Decimal, аудит каждой строки,
4 премиальных блока, квартальный порог плана и годовой перерасчёт Q4.
Явные сопоставления можно сохранить в SQLite и применить при новом импорте.
Настройки и полные неизменяемые снимки расчетов также сохраняются в SQLite.
Требования: Python 3.12+. Полный промпт находится в корне репозитория.

## Установка и тесты

Из каталога `kpi_kam`:

```sh
python -m venv .venv
# Linux/macOS
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -q
.venv/bin/python main.py
```

На Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`.
`main.py` без аргументов открывает GUI. `main.py gui --db PATH` позволяет
задать другую папку данных. `main.py demo` запускает искусственную демонстрацию
ядра. Команды `check` и `calculate` сохранены для работы без GUI (см. ниже).
После установки pytest тесты и ядро работают без интернета и Microsoft Excel.
Сборка exe остается для Phase 6; `build_windows.bat`
будет реализован в Phase 6.

## Экраны GUI

* **Новый расчет**: сотрудник, год, Excel-файл, обязательные Q1–Q4 планы и
  годовой план. Кнопка расчета недоступна при неверных полях, ошибках файла
  или нерешенных сопоставлениях. Процент порога можно изменить для данного
  расчета. Дополнительный переключатель позволяет явно указать фактические
  выплаты Q1–Q3; без него используются рассчитанные квартальные выплаты.
* **Проверка файла**: листы/колонки, исходные и прочитанные строки, товары,
  неизвестные периоды/типы клиентов, отсутствующие цены/пороги и ошибки
  с номером строки. Excel читается в рабочем QThread; SQLite используется
  в главном потоке. Изменение файла сбрасывает готовность прошлого импорта.
* **Сопоставление товаров**: текущий товар, категория и статус. Никаких
  догадок: выбрать из прайса, запомнить алиас или явно оставить неизвестным.
  Пустые названия решаются отдельно для каждой строки. Точные совпадения
  имеют приоритет и не переназначаются. SQLite-алиасы автоматически доступны
  при следующем запуске GUI.
* **Итоги KPI**: годовые карточки, квартальный факт/план/порог/выплаты,
  четыре блока для каждого квартала и зеленый коридор по категориям.
  Нажатия открывают исходные строки или детали премии.
* **Аудит**: все поля из ТЗ, фильтры квартала/клиента/категории/статуса/товара,
  исходные и округленные цены, дельта, причины исключений и суммы внизу.
  «Сбросить фильтры» возвращает все строки после drill-down.
* **Детали премии**: базы, ставки, премии, порог и статус; Q4 показывает
  годовые план/факт, предыдущие выплаты и годовой перерасчет. Нажатие
  выплаты Q4 показывает годовую базу, когда применяется catch-up.
* **Настройки**: пять процентов, фиксированная точность цены (read-only),
  папка будущего экспорта. Сохранение влияет на новые расчеты; исходные
  ставки, планы и аудит прошлых расчетов не меняются.
* **История**: дата, сотрудник, год, источник и выплаты Q1–Q4/за год.
  Двойной щелчок открывает исходный снимок без запуска двигателя или чтения
  Excel. Исходная книга может быть перемещена/удалена — история остается
  доступной вместе с сопоставлениями и всеми строками аудита.

Все денежные поля используют текстовый ввод и Decimal; QDoubleSpinBox для
денег/ставок не используется. Планы никогда не берутся с листа KPI.
Сохранение результата в историю происходит автоматически после расчета.
SQLite-операция атомарна: ошибка записи не оставляет частичный расчет.
Схема Phase 2 расширяется добавлением таблиц; существующие алиасы сохраняются.
Снимки версионированы, Decimal хранится строками, типы восстановления заданы
явным списком. Результат не пересчитывается при открытии истории.
Список истории читает только метаданные и квартальные суммы; полные снимки
отгрузок загружаются при открытии выбранного расчета.

Данные GUI по умолчанию: `%APPDATA%\KPI_KAM\kpi_kam.db` и
`%APPDATA%\KPI_KAM\logs\app.log` на Windows. На Linux используется
`$XDG_DATA_HOME/KPI_KAM` или `~/.local/share/KPI_KAM`. С `gui --db PATH`
лог лежит в папке `logs` рядом с выбранной базой.

Для Linux/CI без дисплея:

```sh
QT_QPA_PLATFORM=offscreen XDG_CACHE_HOME=/tmp/kpi-kam-cache .venv/bin/python -m pytest -q
```

Для обычного desktop-запуска переменная `QT_QPA_PLATFORM=offscreen` не нужна.
PySide6 устанавливается вместе с требованиями; Microsoft Excel и интернет
во время работы приложения не требуются. GUI-тесты не пропускаются и
проверяют реальные сигналы/виджеты Qt, асинхронный импорт и сохранение истории.

## Импорт и расчет через CLI

Из каталога `kpi_kam` (для Windows используйте свой путь к python):

```sh
.venv/bin/python main.py check "tests/fixtures/KPI Трофимов Дмитрий 2026.xlsm"
.venv/bin/python main.py calculate "tests/fixtures/KPI Трофимов Дмитрий 2026.xlsm" \
  --plans 20000000 10000000 0 0 --leave-all-unmatched
```

Это тестовые планы, не реальные планы сотрудника. Последний флаг — явное
разрешение оставить все оставшиеся неизвестные товары несопоставленными.
Без решений по всем таким товарам расчет блокируется. Можно принять решение
для конкретного имени (`--leave-unmatched "Имя"`) или пустого названия
в конкретной строке (`--leave-row 103`). Они остаются в аудите, их выручка
в корректном квартале входит в факт плана.

Явное сопоставление по имени товара текущего прайса:

```sh
.venv/bin/python main.py calculate input.xlsx --plans 1000 1000 1000 1000 \
  --map "Старое имя" "Имя из прайса" --db data/kpi_kam.db --remember-mappings
```

`--map-row 103 "Имя из прайса"` позволяет выбрать товар для строки без
названия. Решения для одинаковых непустых нормализованных названий относятся
ко всем строкам этого товара. Пустые названия всегда решаются отдельно;
их нельзя запоминать как общий алиас. `--remember-mappings` требует `--db`.
Без `--remember-mappings` выбор действует только в данном импорте.
При следующем запуске с тем же `--db` сохраненные алиасы применяются автоматически.
CLI без `--db` работает без сохраненного каталога и алиасов.

`check` выводит листы, исходное/прочитанное число строк, количество товаров,
ошибки с листом/строкой/полем, неизвестные товары и статус допуска к расчету.
Код 0 означает успешную проверку структуры; незавершенные сопоставления
показаны явно. Ошибка структуры, файлового ввода или расчета дает код 2.
Все четыре плана для `calculate` обязательны и задаются пользователем.
Лист KPI не используется для импорта ни планов, ни результатов.

## API импорта и сопоставлений

```python
from app.services.excel_importer import import_excel
from app.services.mapping_service import ImportSession
from app.repositories.alias_repository import AliasRepository
from app.models.domain import Plans

imported = import_excel("input.xlsm")
# На Windows без аргумента путь: %APPDATA%\KPI_KAM\kpi_kam.db.
# На Linux: $XDG_DATA_HOME/KPI_KAM/kpi_kam.db или ~/.local/share/KPI_KAM/.
with AliasRepository() as repository:
    session = ImportSession(imported, repository)
    report = session.validation
    # Пользователь выбирает product.id текущего прайса для entry.key:
    # session.select_product(entry.key, product.id, remember=True)
    # Или явно оставляет товар неизвестным:
    # session.leave_unmatched(entry.key)
    # session.calculate разрешён только когда report.can_calculate == True.
    if session.validation.can_calculate:
        result = session.calculate(Plans("1000", "1000", "1000", "1000"))
```

`ExcelImport` сохраняет SHA-256 источника, имена листов и найденные столбцы,
количество исходных строк, исходные номера строк, данные и ошибки. Исходная
книга никогда не перезаписывается; VBA и внешние ссылки не исполняются.
Заголовки ищутся по именам независимо от порядка столбцов и номера строки,
с нормализацией регистра, пробелов/NBSP и ё/е. Требуются все 10 столбцов
отгрузок из ТЗ и четыре столбца прайса; значения дополнительных полей
(клиент/ЮЛ/задача/комментарий) могут быть пустыми. Имена колонок прайса
поддерживают явные варианты «Продукт»/«Номенклатура»/«Наименование продукта»/
«Товар», «Тип продукта»/«Категория»/«Категория продукта» и варианты зеленой зоны.
Пустые строки пропускаются. Отсутствующие/повторяющиеся колонки, неоднозначные
листы, неверные числа, дубли товаров и неподдерживаемые категории блокируют
расчет; некорректная строка не превращается в нулевой оборот. Исходный текст
сохраняется для аудита; нормализация используется при сравнении.

Денежные числа извлекаются из XML непосредственно в Decimal, включая cached
результаты формул. Допустимы текстовые числа с десятичной запятой или точкой,
корректной группировкой тысяч и знаком; даты, bool и нечисловые значения
не принимаются как деньги. Неизвестный период/тип клиента, отсутствующий порог
и невозможность определить цену отмечаются отдельно и остаются исключениями
в расчетном аудите. Неразрешенное сопоставление требует решения независимо
от остальных ошибок строки.

Id товара детерминирован по нормализованному каноническому названию;
перестановка строк/пробелов/регистра прайса не ломает алиас. Существенное
переименование товара требует явного нового сопоставления. Категория/цена
всегда берутся из текущего импортированного прайса, даже для сохраненного алиаса.
Если его товар отсутствует, алиас сохраняется в SQLite, но не применяется:
отчет отмечает `stale_alias`, и пользователь должен принять решение.
Изменения записываются транзакционно; суммы хранятся как текст Decimal.
Ошибочный импорт не заменяет сохраненный каталог. Результаты прошлых расчетов
остаются неизменяемыми; GUI сохраняет полную SQLite-историю отдельными снимками.

## API

```python
from decimal import Decimal
from app.models.domain import Plans, Product, Shipment, Rules
from app.services.calculation_engine import calculate_kpi

products = [Product("p1", "Товар", "СБКС", Decimal("100"), Decimal("100"))]
shipments = [Shipment(3, "1 кв.", "ЛПУ", "Товар", Decimal("10"),
                      Decimal("1000"), Decimal("100"))]
result = calculate_kpi(
    shipments, products,
    plans=Plans("1000", "1000", "1000", "1000"),
    rules=Rules(),
    paid_history={1: Decimal("0"), 2: Decimal("0"), 3: Decimal("0")},
    aliases={"старое имя": "p1"},
)
```

Один вызов соответствует одному сотруднику/году; вызывающий код отвечает за
разделение импортов. `source_row` уникален в рамках импорта. Все четыре плана
обязательны и неотрицательны. Деньги допускают Decimal, строку или int, но
никогда float, bool, NaN или Infinity. Профиль хранит доли: `0.90 = 90%`.
Планы, правила, денежные итоги, продукты и исходные строки сохраняются в
неизменяемом результате и снимке истории.

* Категория и порог берутся из переданного текущего прайса. Неизвестные/похожие
  названия не угадываются. Точный матч имеет приоритет над явным алиасом.
  Неоднозначный прайс и алиас на отсутствующий id вызывают ошибку ввода.
* Цена сравнивается после ROUND_HALF_UP до 0.1. Равенство проходит.
  При отсутствующей/нулевой цене используется выручка / количество.
* Все строки корректного квартала входят в факт, независимо от сопоставления,
  типа клиента, порога и цены. Неверный квартал остаётся только в аудите.
* Для нескольких ошибок строки показывается первая причина в порядке:
  период, тип клиента, продукт, определение цены, порог, цена ниже порога.
  Все доступные поля аудита сохраняются даже для исключённых строк.
* Обороты возвратов учитываются со знаком, финансовые промежуточные значения
  не округляются до копеек. Контекст расчёта — 50 значащих цифр, изолирован
  от глобального Decimal-контекста. Денежное представление округляется
  до копеек только в `format_money`. Выплата не может стать отрицательной.
* Без `paid_history` предполагается, что разрешённые квартальным порогом
  суммы Q1–Q3 были выплачены. Явный словарь означает реальные выплаты;
  отсутствующие ключи равны нулю. При выполненном годовом плане Q4 получает
  `max(0, годовая расчетная премия − реальные выплаты Q1–Q3)`.
  `annual_payable` — реальные выплаты Q1–Q3 плюс новая выплата Q4;
  при переплате прошлого периода он может превышать расчетную годовую премию.
* При нулевом плане процент выполнения не определён (`None`), а порог
  проверяется как обычно (`actual >= 0`).

В `quarters` есть базы/ставки/премии четырёх блоков и исходные номера строк,
план, факт, порог, расчётная и выплачиваемая премии. `audit` содержит исходную
строку, нормализованный квартал/клиента, продукт прайса, вид сопоставления,
сырые и округлённые цены, дельту, блок и причину исключения.
`green_totals` содержит все 40 сочетаний квартал/тип клиента/категория.
`actual_source_rows`, `included_rows`, `excluded_rows` обеспечивают drill-down.

## Структура

* `app/ui/` — окна и экраны PySide6; расчетных формул в виджетах нет.
* `app/models/domain.py` — модели входа и результата.
* `app/models/application.py` — настройки и сохраненный расчет.
* `app/services/application_service.py` — оркестрация GUI без Qt.
* `app/services/audit_service.py` — фильтры и суммы аудита снимка.
* `app/services/snapshot_service.py` — типизированная сериализация Decimal.
* `app/repositories/application_repository.py` — настройки и история SQLite.
* `app/services/calculation_engine.py` — расчёт и аудит.
* `app/services/product_matcher.py` — чистый exact/alias matcher.
* `app/services/excel_importer.py` — чтение структуры, исходных данных и Decimal.
* `app/services/validation_service.py` — отчет об ошибках и бизнес-исключениях.
* `app/services/mapping_service.py` — решения сопоставления и допуск к расчету.
* `app/models/import_data.py` — неизменяемые результаты импорта и валидации.
* `app/repositories/alias_repository.py` — SQLite-товары и сохраненные алиасы.
* `app/utils/normalization.py` — нормализация, Decimal и формат денег.
* `tests/` — бизнес-правила и regression fixture.
* `resources/` — место для дополнительных ресурсов приложения.

## Regression fixture и ограничения

См. `tests/fixtures/README.md`. Workbook используется только в тестах.
Тестовый XML-адаптер сохранён как независимый путь проверки. Тот же эталон
проверяет production-импортёр и ImportSession; GUI-тесты проходят полный путь
от проверки файла до расчета/истории на этой книге. Экспорт Excel и Windows
упаковка остаются для следующих фаз. Логи CLI выводятся в stderr; GUI сохраняет
вращаемый app.log рядом с базой данных, без названий клиентов.
GUI проверен настоящими Qt-виджетами в Linux offscreen, включая event loop
desktop entry point. Windows-native запуск/сборка в этой среде не выполнялись.
Входные формулы не вычисляются: импорт использует сохранённые результаты.
При отсутствии результата формулы количества/выручки расчет блокируется;
при отсутствии цены применяется revenue/quantity; отсутствующий порог дает
исключение из зеленого коридора. Отсутствующие cached значения всегда
отмечены в отчете. Файлы .xls, зашифрованные и поврежденные книги не поддерживаются.
